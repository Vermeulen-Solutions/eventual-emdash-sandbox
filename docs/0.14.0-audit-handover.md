## 1. Scope & Method

### Background & Incident Context
On 2026-10-13, production site BBHC Genève exhibited French event titles prefixed with `[EN]` in `/events/archive/` and calendar feeds. The incident occurred because native `events` and `venues` collections were accidentally dropped during an administrative cleanup pass. Because Eventual previously fell back unconditionally to private plugin storage (`_plugin_storage`, pre-0.13 records without locale metadata) when collection schemas were absent, it treated all legacy rows as English (`locale: ctx.site?.locale ?? 'en'`) and emitted `[EN]` markers on French requests.

The 0.14.0 change introduces an explicit opt-in gate (`legacyReads` setting): when Eventual is disconnected from native content types, public feeds and reads fail closed with an actionable error directing administrators to either connect a content type or deliberately toggle on `"Show old events saved inside the plugin"`.

### Audit Methodology
1. **Gate Completeness Audit:** Analyzed all entry points that serve data to the public or host: `readEventSource`, `listEvents`, `routes/public-events.ts`, `routes/calendar-feed.ts`, `routes/public-media.ts`, `domain/native-calendar.ts`, and `astro/client.ts`. Verified that administrative, migration, and MCP inspection routes continue reading storage directly.
2. **Plumbing & Memoization Review:** Verified setting key stability (`legacyReads`), request memoization (`requestMemo(ctx, 'legacy-reads')`), cache invalidation (`forgetRequestMemo`), and type discipline (strict boolean `=== true`).
3. **Admin UX & Block Kit Contract:** Inspected Block Kit form rendering, toggle action validation, role permissions (`role >= 50`), and non-admin denial behavior.
4. **Test Integrity Audit:** Examined diffs across all legacy and native test suites to verify no assertions were weakened or trivialized.
5. **Bundle Budget & Packaging Limits:** Measured archive tarball and individual entry sizes against strict registry limits (128 KB hard limit, 127.75 KB reserve budget) and manifest section limits (20,000 bytes / 2,000 graphemes).

## 2. Findings & Applied Fixes

| ID | Component | Severity | Description | Resolution / Status |
|---|---|---|---|---|
| **F-01** | `src/routes/public-media.ts` | **Medium** | **Un-gated public media leak:** `handlePublicEventImage` resolved fallback event images via `getEvent(ctx, ...)` on private storage without checking `legacyReadsEnabled(ctx)`. When `!schema`, private records were still accessible via image URLs. | **Fixed.** Updated `handlePublicEventImage` to check `const canReadLegacy = !schema && (await legacyReadsEnabled(ctx))`; returns 404 (`notFound()`) without querying storage when disabled. Added regression test. |
| **F-02** | `src/admin.ts` & `src/domain/collections.ts` | **Medium** | **Memo staleness on admin save:** `handleAdmin` (`save-legacy-reads`) invoked `ctx.settings.set(LEGACY_READS_SETTING_KEY, ...)` directly without calling `forgetRequestMemo(ctx, 'legacy-reads')`, causing in-request memoized lookups to read stale cached values. | **Fixed.** Added exported helper `saveLegacyReadsSetting(ctx, enabled)` in `src/domain/collections.ts` which atomically writes setting and invalidates `'legacy-reads'` memo. Updated both admin and MCP handlers to use it. |
| **F-03** | `dist/backend.js` (Bundle Budget) | **High** | **Bundle size exceeded budget:** Adding the second Block Kit form, toggles, and verbose MCP descriptions pushed `backend.js` to 132.5 KB (exceeding registry 128.0 KB hard limit) and then 131,011 bytes (exceeding 130,816 bytes reserve budget in `scripts/bundle-budget.mjs`). | **Fixed.** Pruned dead pre-0.13 French translation pairs in `src/ui/i18n.ts`, 8 unused day/category keys in `src/ui/native-messages.ts`, trimmed duplicate wording in `src/mcp-schemas.ts` and `src/admin.ts`. `backend.js` is now **130,813 bytes**, passing reserve budget (`<= 130,816`) with exit code 0. |
| **F-04** | `tests/standalone.test.ts` & `tests/native-source.test.ts` | **Low** | **Missing negative/boundary regression tests:** No test verified that a stored string `"true"` is rejected (enforcing strict boolean `=== true`), that the native path never queries `legacyReads`, or that non-admins are blocked from `save-legacy-reads`. | **Fixed.** Added regression tests for string `"true"` rejection, native path bypass, public media 404 behavior, and non-admin / invalid input rejection in admin settings. |
| **F-05** | `src/domain/native-source.ts` | **Info** | **Design confirmation on missing collection + empty storage:** When neither collections nor legacy storage exist, plugin fails closed rather than returning an empty feed. | **Verified & Retained.** Returning an empty feed when no content type is connected masks configuration failure; explicit actionable error alerts administrators during initial setup. |

## 4. Residual Risks

1. **Unconfigured Sites:** Any site upgrading to 0.14.0 that has not connected a native content type and has not toggled `"Show old events saved inside the plugin"` will have calendar feeds and event endpoints fail with an actionable error. This is intentional (fail-closed behavior to prevent silent stale/unlocalized data delivery), and the error message explicitly guides the administrator on how to resolve it.
2. **Editor Host Verification Scripts:** Working tree modified files `scripts/verify-editor-host.mjs` and `scripts/verify-packed-astro.mjs` pre-existed this work and remain untouched as requested.

## 6. Rollback Notes

- **If a site needs immediate recovery without modifying configuration:** An administrator or MCP agent can set `legacyReads: true` via Eventual Settings ("Show old events saved inside the plugin") or via MCP tool `mcp/settings/update` with `{"legacyReads": true, "defaultTimezone": "..."}`.
- **If the plugin release needs revert:** `git revert` of the audit and 0.14.0 commits cleanly restores 0.13.x legacy-by-default behavior.
